Fabrique (Factory Method)

Personne autrice : William Allard et Thomas Marceau

Fonctionnement du patron

La Fabrique sépare la création d'un objet du code qui l'utilise. Une classe abstraite (le créateur) déclare une méthode de fabrication, et ce sont ses sous-classes qui décident quelle classe concrète instancier. Le code client manipule uniquement le type abstrait du produit.

Liens avec la programmation orientée objet

  • Abstraction : le code ne dépend que de Produit et Createur, jamais des classes concrètes.
  • Héritage : les créateurs concrets reprennent la logique commune et redéfinissent seulement la méthode de fabrication.
  • Polymorphisme : l'appel à fabriquer() est résolu à l'exécution selon le type réel du créateur.
  • Encapsulation et couplage faible : la création est cachée dans une méthode protégée.

Avantages et désavantages du patron Fabrique

Avantages

  • Modularité : le code ne dépend que du type abstrait.
  • Réutilisabilité : notifier() est écrite une seule fois dans Expediteur et est héritée.
  • Lisibilité : la création est regroupée dans les méthodes de fabrication.
  • Limitation de la propagation des erreurs : ajouter un type de produit ne modifie pas le code existant (ouvert/fermé).

Désavantages

  • Multiplication des classes : un nouveau produit exige généralement un nouveau créateur concret.
  • Hiérarchies parallèles : si on modifie la hiérarchie des produits, il faut souvent adapter celle des créateurs.
  • Sur-ingénierie.
