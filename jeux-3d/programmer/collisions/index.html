    Gestion des collisions et la physique

    Contenus de la page

    4-6 Utilisation des composantes modulaires pour les collisions

    Temps requis

    40 minutes

    À propos de la page

    Signaler une erreur

    Concepts de bases

    Les collisions dans Unity sont gérées par deux composants : les colliders et les rigidbody. Les colliders définissent une zone de collision et permettent aux scripts de savoir quand une collision se produit. Par défaut, ils sont rigides et ne peuvent être traversés par d'autres objets. Pour qu'une collision se crée, les deux objets doivent avoir un collider et au moins l'un des deux un rigidbody qui ne soit pas endormi.

    Les colliders utilisés en 3D sont :

    • BoxCollider : collider de forme rectangulaire. On utilise ce collider aussi souvent que possible.
    • CapsuleCollider : collider de forme de pilule ou d'œuf. On utilise souvent ce collider pour approximer des personnages.
    • SphereCollider : collider de la forme d'une sphère.
    • MeshCollider : utilise les données d'un mesh pour gérer les collisions. Ce collider demande beaucoup plus de ressources que les autres, donc on l'utilise seulement lorsqu'un haut niveau de précision est nécessaire.

    Les colliders ont les paramètres suivants :

    • Is Triggers : change le comportement vers le mode trigger;
    • Material : affecte un physic material*;
    • Paramètres de forme : ajuste la taille du collider si différente de la boîte limite du game object; et
    • Layers overrides : effectue une gestion personnalisée des layers pour cet objet.

    Pour agir dans le code lorsqu'une collision se produit, les trois méthodes peuvent être appelées dans un script appliqué sur le game oject qui possède le collider.

    • private void OnCollisionEnter(Collision collision) : lorsqu'une collision commence entre deux objets;
    • private void OnCollisionStay(Collision collision) : chaque frame lorsque deux objets sont en contact; et
    • private void OnCollisionExit(Collision collision) : lorsqu'une collision se termine entre deux objets.

    Le paramètre collision contient les informations sur la collision, comme une référence à l'autre game object.

    Pour les rigidbody, ils sont souvent utilisables sans configuration particulière, sauf changer la masse pour avoir des collisions et une échelle de valeurs réaliste. De plus, si un rigidbody est immobile, il peut arrêter d'enregistrer les collisions. C'est une optimisation interne de Unity.

    Les triggers

    Les triggers sont un type de collider qui, au lieu de fournir une zone de collision rigide, agissent plutôt comme une zone de détection. On les active en cochant la case Is Trigger dans l'interface. Par défaut, il ne peut pas y avoir de collision entre deux colliders trigger* dans Unity.

    Les méthodes pour réagir dans le code sont différentes si le collider est marqué trigger :

    • private void OnTriggerEnter(Collider other) : lorsqu'un autre collider entre dans la zone;
    • private void OnTriggerStay(Collider other) : chaque frame lorsqu'un autre collider reste dans la zone; et
    • private void OnTriggerExit(Collider other) : lorsqu'un autre collider quitte la zone;

    Le paramètre other est le collider de l'objet qui est entré dans la zone. On peut récupérer son game object avec other.gameobject.

    Les kinematics

    Un rigidbody se déplace normalement grâce aux forces appliquées dessus. Toutefois, on peut déplacer un rigidbody en lui assignant une position : c'est ce que l'on appelle un kinematic. Il suffit de cocher la case du même nom dans l'inspecteur pour lui affecter ce comportement. Par défaut, le transform n'est pas synchronisé avec le rigidbody, donc il faut utiliser la méthode MovePosition et Rotate du rigidbody. De plus, ces appels doivent se faire dans la méthode FixedUpdate. Le temps d'exécution entre les FixedUpdate est disponible dans la variable fixedDeltaTime.

    FixedUpdate

    La boucle de physique suit un rythme différent de celle standard. Pour faire un déplacement adéquat, il faut passer par les temps fixed et la méthode FixedUpdate, autrement on peut observer des comportements physiques étranges.

    Restriction sur les mouvements

    Il arrive qu'on souhaite permettre le mouvement dans certaines directions seulement pour un rigidbody. Dans ce cas, on peut utiliser les contraintes pour s'assurer que la physique reste cohérente. Ces restrictions ne s'appliquent qu'aux mouvements automatiques et aux rigidbodies qui ne sont pas kinematic.

    Layers

    Les layers permettent de définir un groupe d'objets dans les comportements physiques. On les utilise souvent pour regrouper les objets qui devraient interagir entre eux ou qui devraient interagir dans les mêmes circonstances. C'est utile pour exclure des cas de collision d'objets. On assigne le layer dans l'inspecteur juste en dessous du nom de l'objet.

    On peut définir les règles d'interaction entre les layers globalement dans le menu Editor > Project settings > Physics > Settings > Layer Collision Matrix.

    Pour chaque collider ou rigidbody il est aussi possible d'inclure ou d'exclure des layers pour configurer précisément les collisions qui doivent être détectées.

    Qualité des collisions

    La qualité des collisions permet de mieux gérer les collisions qui surviennent avec des objets qui se déplacent à grande vitesse. Par contre plus une collision est précise, plus il faut de ressources de calcul.

    D'abord, il faut essayer le mode discrete qui consomme le moins de ressources et fonctionnera pour les collisions à basse vitesse. Si des collisions sont manquées, alors le mode continuous speculative devrait repérer ces collisions à haute vitesse. Ensuite, si la collision n'est toujours pas détectée :

    1. Si la collision est entre un objet dynamique et un objet statique, on utilise le mode continuous;
    2. Si la collision est entre deux objets dynamiques, on utilise le mode continuous dynamic; et
    3. Si la collision est le résultat d'une rotation, alors le mode continuous speculative est le meilleur, même lorsqu'il n'est pas parfait.

    Interpolation graphique

    Le paramètre interpolation permet de définir comment le rendu graphique va s'adapter à la prédiction du mouvement. Cela peut être utile pour éviter d'avoir le visuel d'un objet qui pénètre dans un autre pour la frame où la collision est détectée. Trois modes existent pour les interpolations. Ils sont présentés de celui qui consomme le moins de ressources à celui qui en consomme le plus :

    1. None : l'objet se téléporte de position en position lors du FixedUpdate, cela peut causer du jitter si la caméra suit cet objet;
    2. Interpolate : lisse le mouvement en utilisant la dernière position connue, cause exactement 1 frame de latence entre la position physique et la position affichée; et
    3. Extrapolate : utilise la prédiction du mouvement pour lisser le mouvement. Si une collision se produit en milieu de frame, l'objet peut graphiquement pénétrer la surface avant que le moteur ne corrige. Cette valeur est utilisée pour les objets rapides qui se déplacent en ligne droite.

    Paramètres physiques

    Plusieurs paramètres physiques peuvent être gérés avec les composants de Unity. On détaille dans les sections suivantes la gestion des forces, de la gravité, de l'aérodynamisme (simple), de la friction et de l'élasticité.

    Unity permet aussi une gestion avancée de la physique des véhicules

    Gérer les forces

    Pour appliquer une force dans Unity, on appelle la méthode AddForce sur un rigidbody. Cette méthode applique une certaine « force » sur l'objet. La quantité physique représentée par la « force » appliquée dépend du type d'application.

    • Impulse : une force d'impulsion correspond à un coup donné pour un instant, soit une seule frame. Cette force correspond à un vecteur d'une quantité de mouvement (momentum), soit \(p = mv\). Donc, une quantité de mouvement de 5 appliqué à un objet d'une masse de 2.5 permet d'obtenir un déplacement de 2 m/s. Son effet est instantané.
    • VelocityChange : applique un changement dans la vélocité de l'objet. La vélocité est une vitesse à laquelle on a donné une direction. Le vecteur fourni à la méthode est la nouvelle vélocité. Son effet est instantané.
    • Force : applique une force de façon continue sur un objet, comme un champ de force ou du vent. Cela correspond à la véritable définition physique d'une force. Il n'est pas nécessaire d'appeler fixedDeltaTime, Unity fait adéquatement les calculs. Donc, une force de 1 Newton, appliqué à un objet d'une masse de 2 kg génère une accélération de 0.5 m/s^2.
    • Acceleration : applique une force, mais sans tenir compte de la masse. Cela peut correspondre à un mouvement de personnage, par exemple. La force applique seulement une différence de vitesse. Donc une valeur de 0.5 d'accélération indique qu'après 1 seconde, la vitesse sera de 0.5, après 2 secondes de 1 et ainsi de suite.

    La démonstration de chaque type de force est présentée dans le projet Demo application physique.

    Gravité

    La gravité peut être activée ou désactivée pour chaque objet. Donc, un objet peut être dynamique sans subir la gravité. Pour modifier la valeur globale de la gravité, on peut modifier les paramètres de physique dans : Edit > Project Settings > Physics > Settings > Shared. Par défaut la valeur est de -9.81 m/s^2 en y, soit la gravité terrestre.

    Aérodynamisme

    Dans Unity on résume les paramètres aérodynamisme avec le damping (amortissement). Plus une valeur de damping est grande, plus l'objet résistera au mouvement. Il y a un paramètre pour le mouvement (linear) et un pour la rotation (angular).

    Physic materials

    Les physic materials s'appliquent sur les colliders et permettent de définir comment ils se comportent lors d'une collision. Par défaut, une surface est molle et rugueuse. Les paramètres du physics material sont :

    • Dynamic friction : friction appliquée lors du mouvement. Une friction de 0 indique aucune friction (glace), alors qu'une friction de 1 indique une surface rugueuse comme du caoutchouc. La valeur par défaut est 0.6.
    • Static friction : friction appliquée lorsqu'un objet n'est pas en mouvement. Pour se mettre en mouvement, il est nécessaire d'excéder ce point de friction initial pour se mettre en mouvement. Il utilise la même échelle de valeurs que la dynamic friction. La valeur par défaut est 0.6.
    • Bounciness : définit l'élasticité de la surface. Plus une surface est élastique, moins qu'il y a d'énergie perdue lors d'une collision. Une élasticité de 0 indique une surface molle comme un matelas qui absorbe le mouvement et 1 indique une surface rebondissante, comme un trampoline. La simulation peut ajouter de l'énergie dans un rebond, donc permettre le mouvement perpétuel ou même augmenter le rebond. La valeur par défaut est 0.
    • Friction combine et bounce combine : définissent comme les valeurs de chaque physic material se combinent lors d'une collision. Les valeurs possibles sont : maixmum, multiply, minimum et average (valeur par défaut). Les valeurs sont considérées dans cet ordre de priorité. Donc, dans une collision entre deux objets, l'un en mode multiply et l'autre en mode average, la collision est gérée comme multiply.
