    Signaler une erreur

    Le pool d'objets est un patron de conception qui permet de réutiliser des instances existantes au lieu de constamment créer de nouvelles instances des mêmes objets.

    Le pool est responsable de la création des objets. Sa méthode GetObjet permet d'encapsuler cette gestion. L'algorithme de la méthode est simple.

    Limiter les instances

    Certains pool peuvent gérer un nombre important d'objets qui ont peu d'influence sur le jeu. Par exemple, imaginez des branches qui tombent d'un arbre quand on le coupe. Pour éviter de trop gérer d'objets on pourrait limiter le nombres d'instances de branche qui peuvent être générés dans le jeu.

    Structurer les objets du pool

    Le pool d'objets risque de créer beaucoup d'instances. Pour éviter la dispersion des instances, on va tendre à les regrouper sous l'objet du pool. Si l'objet a besoin d'avoir un parent particulier pour suivre un mouvement, alors il devra être assigné à son parent pendant son utilisation et revenir sous le pool lorsqu'il est innactif.

    Gérer de multiples pools

    Lorsque les pools deviennent nombreux, on peut écrire un code générique pour gérer les pool en exploitant les traitements communs pour réduire le code à écrire. On peut utiliser deux approches :

    1. Utiliser l'héritage : le code est plus simple à personnaliser, mais il faut faire une sous-classe pour chaque type de données à gérer.
    2. Utiliser la généricité : on peut ajouter le pool sur n'importe quel type d'objet qui définit une interface commune, mais le code est plus complexe et légèrement plus lent. Cette technique pourrait poser des ralentissements avec un pool utilisé intensivement.
